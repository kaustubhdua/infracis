# Production release runbook

This file is the source of truth for release gates. A checkbox is only complete when a run, output, URL, or reproducible evidence is linked here. Never mark a gate green based on code presence alone.

## P0 — dependency/security verification
- [ ] Record candidate commit SHA and GitHub Actions run URL.
- [ ] Green on that exact SHA: `npm ci`, `npm audit --omit=dev --audit-level=high`, tests, lint, typecheck, production build.
- [ ] Review dependency audit findings including development dependencies; resolve or document accepted risks.
- [ ] Confirm the lockfile was regenerated by npm and is consistent with package.json.
- [ ] Review Next.js advisories and deployed version before release.

## P0 — shared provider throttling and caching
- [ ] Configure dedicated Upstash Redis REST URL/token for the Infracis deployment; do not reuse another app's data store.
- [ ] Verify API requests fail closed with 503 in production if shared limiter credentials are absent or the store is unavailable.
- [ ] Add provider-specific shared cache with bounded TTL and source-specific keys.
- [ ] Run concurrent-request test against at least two independent app instances; verify aggregate Nominatim outbound rate stays <= 1 request/second across the app.
- [ ] Verify retries, timeouts, cache misses, expiry, and Redis outage behavior.

## P0 — API security
- [ ] Only trust hosting-platform-supplied client IP headers; never use the leftmost arbitrary X-Forwarded-For value as an identity.
- [ ] Run request-body abuse tests (malformed JSON, body over limit, missing fields, wrong types, coordinate bounds, huge strings, concurrent floods).
- [ ] Validate upstream JSON shape, required fields, numeric ranges, and arrays before use.
- [ ] Ensure errors returned to clients do not leak upstream response bodies, secrets, or stack traces.
- [ ] Confirm no credentials or private env values are committed or exposed in NEXT_PUBLIC_* variables.

## P0 — saved report persistence
**Current release decision: cloud save is deferred.** Browser-local saves and JSON export are not cloud persistence. Do not enable a cloud-save UI until a dedicated authorized Supabase project exists, migration is applied, authenticated CRUD is implemented, and cross-user RLS tests pass.
- [ ] Dedicated Infracis Supabase project approved and selected.
- [ ] Apply migration and verify migration history/table/index/policies/grants.
- [ ] Authenticated create/read/update/delete integration tests.
- [ ] Cross-user isolation tests for SELECT, UPDATE, DELETE, and attempts to change owner.
- [ ] Explicit UI labels: reports are stored in this browser only until cloud persistence ships.

## P1 — real-data pilot
- [ ] Choose and record a pilot geography, test date/time, and sample of at least 20 varied locations (dense urban, residential, edge/rural, ambiguous address, no-match).
- [ ] For each sample record query, resolved coordinates/label, source response status, returned item count, timing, provider attribution, and known limitations.
- [ ] Independently spot-check a sample against source pages/maps; do not treat OSM absence as proof of absence.
- [ ] Report coverage as measured counts/rates with denominators; no fabricated completeness percentage.
- [ ] Document all failed, ambiguous, stale, and partial results.

## P1 — full user journey and accessibility
- [ ] Mobile (at least 360px wide) and desktop: search, map pick, evidence detail/source links, comparison, export, local save/reopen/delete, provider failure.
- [ ] Keyboard-only navigation and visible focus; screen-reader labels; contrast; reduced motion.
- [ ] Automated accessibility scan and manual review with evidence attached.
- [ ] Verify no horizontal overflow, clipped text, empty states, and loading/error states.

## P1 — deployment
- [ ] Verified live URL and Vercel project connected to this repository.
- [ ] Record deployed commit SHA and ensure it equals the release candidate SHA.
- [ ] Smoke-test health, analyze, compare, provider-backed real queries, invalid input, throttling, and upstream outage.
- [ ] Monitoring and alert routing configured; define rollback trigger and prove rollback path.
- [ ] Verify provider terms: public Nominatim <=1 request/sec app-wide and attribution; Open-Meteo free API only for non-commercial use, commercial plan/self-host if commercial, CC BY 4.0 attribution.

## P2 — product validation
- [ ] Interview at least 5 target buyers/renters; record anonymized notes and observed pain points.
- [ ] Define a primary success metric (e.g., proportion of pilot users who identify and correctly cite at least one actionable due-diligence check) and guardrails.
- [ ] Run a small usability test and publish results including failures, not just positive quotes.
- [ ] Create a feedback intake path, owner, review cadence, and decision log.

## Current environment constraints
- No dedicated Infracis Supabase project or Infracis Vercel project was found in the connected accounts at the last check. Do not apply migrations to unrelated projects, deploy to unrelated projects, or claim a production URL until access is configured.
- Public Nominatim is a constrained shared service; the current per-process spacing guard is not a production-wide limiter.
- Open-Meteo's free API is non-commercial only; the product's business model/use must be decided before launch.
